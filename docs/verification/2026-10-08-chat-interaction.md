## 复现与定位

截图对应原会话 `20130cf6-36a2-4991-9974-998ddac20e10` 的两轮澄清回执均有四个选项。当前旧部署重开这段历史也能显示选项，因此不能归因于这两轮模型没有生成选项。截图与旧前端行为一致；具体浏览器缓存成因未做事后假定。原回执只读留存于 `data/reports/chat-interaction-20261008/user-reported-conversation.json`。

固定 loading 的原因可直接在调用链确认：聊天发送未传入已有事件回调；普通 content delta 也不包含模型生成的工具参数中的澄清问题。

## 改动

- 澄清展示为选项卡，显示序号与继续箭头；点击直接发送当前选项，支持自由输入。读取 `facts.meta.clarification`，兼容 `planning.spec` 回执；不把来源 JSON 当成用户选择界面。旧澄清仍受 run/conversation/version 约束。
- 从真实事件显示接收、等待模型、理解上下文、筛选、语义处理、检索、核验相关性、整理结果及等待秒数。不会展示尚未执行的阶段，也没有假进度百分比。
- 从流式工具参数中提取顶层 `CLARIFY.clarification` 的增量快照，转义、Unicode 和未完成字符串有专门处理；内部推理、原始 JSON 不进入正文。临时问句没有可点击选项；回执成功后才显示正式选项。
- SSE 断线按最后序号回读同一个 run，去重并排空多页 journal 后才判断终态，不重新发送问题。失败、取消、超时清理连接与定时器。
- 停止按钮移至输入框；阅读上文时不强制跟随滚动。已完成的真实过程可折叠查看。选项在窄屏单列，减少动态效果设置关闭动画。
- HTML 与资源有内容指纹和重新验证头；新界面定期检查资源版本，后续服务更新时提示刷新，不在问答途中自动刷新。
- 同一组方向被再次解释时，保留澄清的原始目标，避免“有哪些方向？”覆盖“系统设计题”。
