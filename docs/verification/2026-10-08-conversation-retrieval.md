# 对话检索与反馈记忆：实现、真实测评和验收

本轮按 [Spec](../plans/2026-10-08-conversation-retrieval-spec.md) 完成 context 澄清、相关性筛选、对话工作台和反馈记忆闭环，并部署到本机 8000。功能验收通过；检索仍有边界误报和已知正例未进入 Top 15，不能据此宣布全库质量达标。

## 根因与实现

原 Agent 设计反馈执行 HYBRID / NOT_REQUESTED，RRF Top K 没有语义过滤；泛设计词、向量领域邻近和按页大小截断会混入普通后端题。Harness 历史计划只有字面 `harness`，缺少 context/memory 的概念理解。同时，待澄清目标、历史列表、恢复后的反馈事件及完整原回答留证不完整。

现在由 Pi 判断对象、任务和关键条件是否足够。仅领域缺失且会改变候选集合时先 CLARIFY；保存原问题和选项，短答补齐目标后检索。明确 Agent、秒杀、线上内存问题直接查询，当前明确要求覆盖会话与偏好。CLARIFY 不调用 ES、embedding 或 rerank。

语义检索默认 HYBRID_RERANK。`search_query` 可以语义扩展，`relevance_query` 还原用户意图；每道候选按其自身对象和任务证据评分，仅 grade >= 2 展示。重排不可用时默认不展示未经核验的候选，明确提示重试；用户仍可显式查看原始召回。列表、统计与完整 SQL 排名保持原路径。

界面采用灰白侧栏、会话搜索、居中回答、底部输入框和澄清选项；新回答与历史使用同一渲染及事件。反馈由服务端关联当前用户的持久 run，保存原问题、回答、全部结果和版本。重新检索使用新 request_id；恢复原请求保留幂等语义。

记忆分为会话状态、明确保存的默认偏好和窄范围查询纠正。反馈可以立即用于重检；只有明确选择“记住”才跨会话生效，按规范化后的同一查询匹配，可以停用并检查版本。反馈及纠正后的回执自动成为可导出的回归样本。这是本轮自进化闭环的范围；全局提示词、模型与语料的修改仍须独立测评。

## 真实测评

预测前封存七场景十轮协议，分别采集旧部署、v8、v9 + rerank v5、v9 + rerank v6 的真实 Pi / 模型 / ES 回执。原始失败均保留，文件不覆盖。语料和索引均为 revision 293，任务分类版本 30；没有发布实验标签或重建语料。

| 检查 | 旧部署 | 最终候选 |
|---|---|---|
| 十轮动作符合预期 | 9/10 | 10/10 |
| 无上下文“场景设计题” | 直接 LIST | CLARIFY，返回四个选项 |
| 明确“agent场景设计题” | SEARCH | SEARCH，无多余澄清 |
| Harness 已知 context/memory 正例 | 0/3 | 2/3，第三条未进入 Top 15 |
| 不存在的量子解码设计样本 | 返回 20 道无关题 | 返回 0 道 |
| Agent 记忆后的“这类题” | SEARCH，但范围有泛化 | 还原 Agent 上下文记忆目标 |
| 随后改看秒杀 | 切换主题 | 清除 AI 范围，返回 7 道业务题 |

对四个单轮查询的全部返回题干做了开发 Agent 逐条审核。相关包括直接问题及明确的紧密子任务；仅共享领域或可能答案中的组件不算。下面是 **返回集合 Precision**，不是全库 Recall，也不是独立人工 Gold。

| 查询 | 旧部署：相关/返回 | 最终候选：相关/返回 |
|---|---:|---:|
| Agent 场景设计 | 17/20，85% | 19/20，95% |
| Harness 相关问题 | 13/15，86.7% | 15/15，100% |
| 高并发秒杀设计 | 9/20，45% | 7/7，100% |
| 线上内存增长排查 | 10/20，50% | 10/11，90.9% |

历史 Agent 反馈中的令牌桶、分布式 ID、普通缓存三个负例均未进入最终返回。本轮配对旧部署也没有命中这三个 ID，不能把历史反馈与新 before 拼成“3 → 0”的配对提升。

首次 v8 对明确 Agent 查询仍发起澄清，保留为失败。v9 修复动作后，秒杀结果仍有 4 道通用 Redis 题，7/11；独立原始意图还不够，进一步要求候选自身的业务证据后收窄为 7/7。最终仍返回一条泛 AI 解说架构和一条泛 Full GC 排查，分别在本次 Agent / 内存需求审核中判为弱相关。这两个边界没有被隐藏或计作通过。

SEARCH 耗时中位数约 **14.2 秒 → 29.9 秒**，最终澄清轮约 4.4 秒。默认筛选增加一次模型相关性判断；这些是少量串行开发请求，不是生产延迟分位数。既有模型串行门及间隔继续生效。

## 页面与记忆闭环验收

在真实 8000 页面完成了以下操作，并保存对应持久回执：

1. 新对话输入“场景设计题”，先显示澄清；点击 Agent 应用设计后返回真实题目。
2. 从回答提交明确标记为验收的反馈，选择记住并重新检索：20 道一般 Agent 设计题收窄到 6 道上下文/记忆题。服务端留证仍包含原始全部 20 道题。
3. 新会话重复“Agent 应用设计”，没有携带 feedback_ids，仍按查询记忆返回 6 道相关题。
4. 在查询偏好页停用该记忆，版本 1 → 2；再次新会话查询，恢复为一般 Agent 设计范围、返回 20 道。
5. 页面导出回归样本，包含原反馈、原完整回执和使用新 request_id 的纠正重检回执。验收记忆最终为 inactive；原有用户反馈未改动。
6. 搜索并恢复 Harness 历史回答，原问答仍有来源、反馈和重新检索操作。390 像素窄屏可打开历史列表，没有横向溢出；桌面和窄屏截图留存。

## 工程验证与部署

- Python 全量 **404 通过 / 1 跳过**；最后受影响的查询、反馈、Web、重排回归 **42 通过**，标准 uv 入口的新增对话回归另有 **7 通过**。Pi / 前端 **18 通过**，应用脚本语法与 diff 空白检查通过。
- 覆盖澄清零检索、原目标继承、检索词与相关性意图分离、默认筛选失败不冒充核验结果、原反馈完整留证、重检新请求、记忆版本与停用、用户隔离、历史游标分页与作用域。
- 常规 Docker 构建遇到宿主镜像镜站 DNS 超时。使用已有依赖镜像离线安装新 wheel、更新 Pi 运行层并完成 Compose 健康检查；没有修改宿主网络配置。安装包源码、提示词和页面资源的 17 项 hash 与工作区一致。
- 最终默认 query_agent_v9、rerank_v6_object_evidence；Fast Decision 关闭，开发任务分类政策保持 KNOWN。原 extract / task 设置、语料及分类事实保持既有版本。
