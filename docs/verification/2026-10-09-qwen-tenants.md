## 正式验收与限制

正式增量最终为 17 个冻结文件；109 个受保护原文件的 SHA 保持一致，八个服务（原七个及独立 Qwen）均 active。Alembic head 为 `e937fb9c2160`，query v13 / rerank r14 / corpus 与 index 293 保持；原共享抽取及 embedding 配置保持。初次备份目录为 `/home/dylan/services/interview-intelligence/backups/qwen-tenants-20261009T083822Z`，身份适配的修复备份为 `/home/dylan/services/interview-intelligence/backups/qwen-rerank-20261009T091509Z`，均包含一致性数据库备份、受影响源码和私有环境。修复未改变环境或迁移。回退保留新增表与密钥加密配置，不删除新账号数据。旧匿名历史保留在库中，不自动分配给新注册账号。

首两次 smoke 的失败属于验收输入：先设置 JAVA 偏好却与无语言过滤 SQL 比较，以及把会被基础模型规范化移除的末尾换行当成非法 Key。修改验收顺序及使用 Key 中间换行后通过，正式源码没有为这两项修改。原回执保留。

窄范围 JAVA/Redis 的 20 候选重排实际完成，r14/VERIFIED/0 无效候选，但该范围下持久化查询没有结果。首次宽范围 50 候选返回合法 JSON，却只包含 39 个唯一编号，11 个重复、11 个遗漏；原 r14 正确拒绝了这一结果，后续重试耗尽预算。单独只读复现保存了原始响应，确认不是显存、上下文或输出截断。

修复只在系统 Qwen 的 SDK 边界将候选编号作为结构化对象的必填键，并以显式 rank 还原原有列表；个人提供方保持原接口。编号缺失、重复或额外编号仍拒绝，证据和行级 PARTIAL 处理继续由原 r14 校验。流缓冲期间持续检查取消和总期限，并保留真实 usage/model。Top50、六次总调用预算及检索源码没有改变。最终宽范围查询成功；这次返回 1 条经过核验的结果，但并非作为查询来源的那条题，因此不声明精确排名命中率。首次失败与修订后的结果分别保留。

Qwen 是官方 Qwen3-8B Q4_K_M，在实际 L20 空闲资源下使用 24,576 token 上下文和单个推理 slot，实际占用 6,760 MiB GPU 显存。独立模型九项实际协议验收通过，见 [模型验收](2026-10-09-qwen-runtime.md)。离线工程测试和这次功能验收不能代表完整检索质量，也不构成容量或多实例恢复保证。
