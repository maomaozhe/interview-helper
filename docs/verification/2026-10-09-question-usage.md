# 2026-10-09 题目使用与复习验收

已实现并部署到本机[使用与复习](http://localhost:8000/#usage)。按当前账号分别记录候选、核验通过、检索返回、SQL 题库浏览次数和最近时间，复习次数与掌握状态沿用个人复习记录。支持按主题、公司、统计期、未入候选、未返回、返回未复习和待复习筛选，也可按低召回、高召回、真实面试频次或复习缺口排序。设计见[Spec](../plans/2026-10-09-question-usage-spec.md)。

使用事件按完成的请求、标准题去重，同一请求重放或多次调用工具不会重复增加；失败和取消不计。计数保存于独立 PostgreSQL 表，按账号隔离，向量与语料版本独立维护。统计从启用时开始，旧评测日志未作为练习灌入。零计数仅表示所选统计期内未观察到，不能独自证明索引或向量有问题。缺少完整候选审计的检索器明确显示观测不完整。

## 相对原来增加了什么

| 原来 | 现在及用途 |
| --- | --- |
| 有检索日志和复习状态，缺少逐题使用覆盖 | 能区分“从未进入候选”“进入候选但没返回”“返回过但没复习”，据此选择排查或复习入口。 |
| 最终 Top K 容易被当成全部召回 | 保存 BM25/Dense 前100或 Hybrid 融合池最多50个候选，核验合格但被分页截断的题仍计核验通过。 |
| 重检、工具重试、评测会混淆使用频次 | 成功的新 run 增量；同 run 多工具取并集、回执重放不增加；显式 evaluation 事件单独保存。 |
| 复习和找题需要另行对照 | 清单及详情显示五类次数，支持直接复习和记录当前题的问题。 |

次数表示服务的完成记录，不等于向量质量、实际阅读或自动掌握。主题/公司筛选决定当前有效题目集合；次数来自这些题在所选使用期内的全部个人记录，复习采用全历史。当前只支持已有的一次 REDIRECT 归并；失败 run 中已执行但未完成的候选不计。

## 页面验证发现的修复

1. 原初始化逻辑会在打开统计页时后台查询题库，产生用户未实际浏览的次数。题库改为首次进入时加载；已有会话结果只恢复展示。刷新统计页也不会发起检索。
2. 无模型示例使用直接 GET 列表接口，原参数编码把空复习状态数组变成 `review_statuses=`，触发 422。空数组现在不发送，多个状态按重复查询参数编码，首次打开题库可正常浏览。
3. 使用API返回日期对象时JSONResponse不能序列化，修为带UTC时区的ISO字符串；使用期、最近返回和复习日期回归通过。
4. 实际GET评测请求被误报用途冲突：FastAPI查询模型将默认practice也标记为已提供。改用真实查询参数判断显式值；同一探针由400变为200，明确冲突仍返回400。首个失败回执保留在`http-smoke-v1-failed.json`，没有执行检索或新增模型调用。

专项13个用例覆盖失败/取消不计、完成后恢复只计一次、新重检增量、多工具去重、原始检索与核验分开、部分异常候选、缺审计提示、账号隔离、当前生效范围、使用期、复习到期、合并去重、分页和迁移。PostgreSQL活体测试使用6个工作线程写入24个新请求，再逐个重放；同题计数仍24，其他账号为0。专项、全量及活体结果有重叠，不相加为通过率。
