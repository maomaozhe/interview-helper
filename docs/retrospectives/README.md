## 状态含义

`status` 是文档状态；`resolution` 是指定 `resolution_scope` 内的问题处理状态：

| resolution | 含义 |
| --- | --- |
| `open` | 问题或质量门槛未解决，可以有局部进展 |
| `mitigated` | 症状或部分路径已缓解，仍有未闭环问题 |
| `resolved` | 指定范围有修复及验证证据，不涵盖范围外未知项 |
| `reopened` | 原已解决范围再次发生有证据的失败，保留旧结论并追加进展 |

`verified_at` 是核对来源的日期；`runtime_verified: false` 表示本次未运行核验。历史通过不证明当前线上仍符合结论，未执行的测试只能作导航。

## 新增与维护

先按 [Agent 工作方式](../reference/agent-workflow.md) 留下事实、假设、检查与简要决策依据。有复用价值再提炼；同根因优先更新已有 PIT，新机制才分配新编号，文案小改无需新篇。下面是最小模板：

```yaml
---
id: PIT-NNN
status: current
resolution: open
resolution_scope: 本篇限定的问题范围
scope: historical-report-and-workspace
verified_at: YYYY-MM-DD
runtime_verified: false
tags: []
sources:
  - path: md/issue.md
  # 可补源码路径及 symbols: [Class.method]
tests: [] # 仓库相对路径，仅列存在的测试
---
```

正文按需要合并小节，保留以下内容即可：

1. **30 秒回忆**：症状、关键原因、有效处理与限制。
2. **事实与定位**：触发/环境/影响、原编号标题和来源链接；已证实、假设、未知分开。同事件不同机制分别说明。
3. **尝试与处理过程**：实际操作、失败结果、后续选择及依据；未做过的不写成失败尝试，没有当时记录的决策标为后续归纳。
4. **验证与未解决项**：输入/版本、命令和结果、部署依据、未执行及仍失败范围、下一步。
5. **防复发与自测**：排查顺序、源码/测试入口，已有与待补措施分开；两道理解题及答案要点。

变更状态时同步本索引、专题和必要的 [来源映射](SOURCE-MAP.md)；稳定契约再更新 [业务不变量](../reference/invariants.md)，能力判断变化才更新 [状态摘要](../status/current.md)。

[原问题日志](../../md/issue.md) 和 [历史验收](../verification/) 保留原始事实、数字、失败及结论；新证据按日期追加或另建记录，允许修正纯导航链接，不覆盖旧结果。复盘只摘必要结论并引用证据，不复制凭据、私人会话或来源全文。
