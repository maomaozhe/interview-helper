# Agent 工作方式：记录、核查、决策、验证

本页集中维护调查、实施和交接的记录方法；需要记录时查阅。日常任务入口与硬约束见 [AGENTS](../../AGENTS.md)，已有故障按 [症状](../retrospectives/README.md#按症状快速查找) 查阅。

## 先留下最小工作记录

非简单任务在首次实现前，用下方 [短记录](#可直接追加的短记录) 写目标/范围、事实、假设和下一步检查，优先追加已有任务；无合适记录时才在 `docs/plans/` 建短计划。故障过程优先沿用 `md/issue.md` 的条目和编号。

纯文案或路径修正可在任务回复中说明依据及意图。开始前检查工作区，保留已有改动；业务代码、配置、语料和个人状态分别限定范围。

## 用事实收敛原因，再选择方案

1. 按任务查契约和相关 PIT，从真实入口、源码字段、装配及输入身份核查，不猜路径、数据库列、模型名或部署版本。
2. 区分现象、假设与证实原因；用低成本只读检查、确定性重放或小范围测试辨别。外部调用沿用已授权范围、预算和共享锁。
3. 实施前记选定方案、简要理由、代价和验收条件。保留可复核依据，不记录大段推演或每一步内部思考。

## 每次失败先记录，再决定是否重试

重试前保存第一现场：操作、时间/环境与版本、可用错误码、关键输入身份、实际结果、调用/预算和证据路径。

- 没有新证据时先更新假设或缩小检查；保留有效草稿/检查点，不降低业务校验。
- 接口、模型、格式/引文、网络/配额、检查器和语义错误分别归因；来源不足写“未知”，传输或检查器问题不计为语义通过/失败。
- 不通过隐藏失败、放宽断言、修改参考标签或抬高预算把失败改写为成功。

有在途调用或未知 usage 时保留不确定性，避免续跑时把预算重置为零。重放和恢复沿用请求身份与幂等规则。

## 实施后按预先条件验证

按变更选择测试及真实入口，记录命令、数据/环境、结果、跳过项和未覆盖范围。工程检查、业务断言、语义审核、安装包及部署分别取证；失败先保留结果再更新假设。

中断或交接时补已完成步骤、有效产物、失败尝试、预算/请求身份、阻断与下一步。接手先读检查点，避免重做成功步骤或重复外部写入。

## 将有复用价值的结果沉淀

先在原条目补结果与依据；有复用价值再按根因更新已有 PIT，新根因才建篇，格式及索引同步见 [复盘维护](../retrospectives/README.md#新增与维护)。区分已有防复发措施、待补机制与操作建议；未解决项保留 open/mitigated/reopened。

当前规则按 [页面映射](../README.md#维护方式) 归并，长期取舍放 `docs/decisions/`，日期验收放 `docs/verification/`。不为小改动同时新建计划、验收和复盘，也不把同一结论复制多处。

完成后，已被当前页完整覆盖的施工清单和重复总结可删除；清理前核对入链、代码读取/哈希依赖。独有决策、原始失败、验收事实和未解决项继续保留，不因日期旧而删除。

## 可直接追加的短记录

```text
目标/范围：
已知事实与证据：
假设及待区分点：
下一步检查与预期信号：
选择方案与简要理由：
本次尝试及实际结果：
验证、剩余问题与下一步：
关联 PIT / 原条目 / 产物：
```

记录里引用必要证据即可，不复制凭据、个人会话或私有来源全文。旧记录按原始时间保留；新证据改变结论时追加说明并链接，不覆盖旧失败。
