# 已观察故障与限制

## 真实导入的超时

2026-09-30，短样本的 Schema、向量、去重和重排预检成功；两篇实际文档的后台试运行遇到 `APITimeoutError`。默认请求超时从 60 秒改为可配置的 180 秒，并增加流式抽取。只有收到完整终止事件、通过 JSON Schema 和原文证据校验的结果才允许发布。修改后两篇均完成处理，一篇发布 8 次提问，一篇排除；之前的超时仍保留在运行历史中。

## 同目录的旧导入程序

本机另有旧导入程序直接构建 extractor，缺少当前 worker 的串行门、预算和语义去重，并持续收到 `404 UnsupportedModel`。已经停止该旧程序并移除旧入口；当前导入统一由 API 队列交给 worker。旧运行的未知 usage 不会被估算成已知的零消耗。

## PostgreSQL 字段长度

完整去重版本指纹曾超出 `PipelineRun.embedding_version` 的 64 字符上限。现保存 SHA-256 指纹，完整版本保留在配置快照；真实 PostgreSQL 插入才暴露了这个 SQLite 不会拒绝的问题。

## 重启与错误止损

单文档子运行曾被重启恢复误认为顶层批次。现在孤立的子运行标记失败，只有带文件列表的顶层批次被接管；每篇已完成路径持久记录。OpenAI 与 HTTPX 两类接口错误都参与批次止损，鉴权、模型配置或限额错误后保留剩余文件，不继续消费调用。

## 来源路径跨宿主

旧版 Windows 程序留下的绝对快照路径无法在 Linux 容器中读取。来源 API 现在从配置的快照目录按文件 hash 定位，随后核验原始字节；缺失和损坏分别给出明确错误。真实得物帖的来源读取已验证。

## 尚未验证的质量

人工 gold 仍是草稿；不能报告抽取 F1、SAME Precision、Recall@10 或路由准确率。超过 20,000 字符的文档仍会明确拒绝，完整语义分段和阶段缓存尚未实现。当前 190 篇输入的最大长度为 16,347 字符，但这不替代通用长文支持。
