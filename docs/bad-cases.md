# 已观察故障与限制

## 真实导入的超时

2026-09-30，短样本的 Schema、向量、去重和重排预检成功；两篇实际文档的后台试运行遇到 `APITimeoutError`。默认请求超时从 60 秒改为可配置的 180 秒，并增加流式抽取。只有收到完整终止事件、通过 JSON Schema 和原文证据校验的结果才允许发布。修改后两篇均完成处理，一篇发布 8 次提问，一篇排除；之前的超时仍保留在运行历史中。

## 同目录的旧导入程序

本机另有旧导入程序直接构建 extractor，缺少当前 worker 的串行门、预算和语义去重，并持续收到 `404 UnsupportedModel`。已经停止该旧程序并移除旧入口；当前导入统一由 API 队列交给 worker。旧运行的未知 usage 不会被估算成已知的零消耗。

## PostgreSQL 字段长度

完整去重版本指纹曾超出 `PipelineRun.embedding_version` 的 64 字符上限。现保存 SHA-256 指纹，完整版本保留在配置快照；真实 PostgreSQL 插入才暴露了这个 SQLite 不会拒绝的问题。

## 重启与错误止损

单文档子运行曾被重启恢复误认为顶层批次。现在孤立的子运行标记失败，只有带文件列表的顶层批次被接管；每篇已完成路径持久记录。OpenAI 与 HTTPX 两类接口错误都参与批次止损，鉴权、模型配置或限额错误后保留剩余文件，不继续消费调用。

## 来源路径跨宿主

旧版 Windows 程序留下的绝对快照路径无法在 Linux 容器中读取。来源 API 现在从配置的快照目录按文件 hash 定位，随后核验原始字节；缺失和损坏分别给出明确错误。真实得物帖的来源读取已验证。

## 工程系统设计题被示例与旧范围窄化

2026-10-08，用户从 Agent 设计纠正为“我要的是工程系统设计题，类似设计一个排行榜这种”，线上只返回一道。规划把排行榜示例当成唯一对象，并沿用 `SYSTEM_DESIGN + coding_focus=ENGINEERING + KNOWN` 硬筛。宽类别中的例子不能排除其他系统设计，新的工程设计目标不能继承旧 Agent 隐式范围；`ENGINEERING` 表示工程编程任务，不能替代系统设计题型。用户明确的筛选仍须保留。

现已区分宽类别举例、明确“只要排行榜”和技术解答，使用同范围的已验证原始问法、任务类型及独立范围复核，按独立设计单位判断，避免要求整套业务系统或用邻近主设计题升级当前局部追问。新增软 `preferred_question_type=SYSTEM_DESIGN` 候选支路并穿透 Pi 工具 schema 白名单；软支路词法/语义权重为 1:2，同时保留全库 2452 题资格及类型外候选，不能把 195 题偏好资格变成硬过滤。每条结果仍须通过任务、引文、对象、焦点和独立范围校验。

开发中曾因整批 schema 校验失败而重新规划并耗尽预算，历史首错字段未保存，不能事后断言具体字段。现对可识别候选逐行严格校验，单行异常隔离为 `INVALID_SCHEMA` 并传递部分结果状态，不补默认值、不冒充负相关、不触发整批重试；批次意图及完整唯一候选 ID 集合仍严格校验，模型故障不能回退到未经验证的列表。

2026-10-09 发布并公开复验后，原会话同一句话从 1 道增至 17 道，独立原文审核为 17 主设计、0 邻近、0 负例，原先三轮历史逐字段不变。隔离覆盖请求返回 15 主设计、1 邻近、0 负例，固定参考命中 15/23；仍有 7 道参考未入池、1 道被主重排误拒，邻近题及漏召回均保留。该参考由 Agent 审核，非人工冻结金标，也非全库穷尽集合。公开原请求耗时 138.03 秒，性能仍待改进，不能以本次定向验收关闭全库质量、完整 V1 或 H01 问题。修改边界见[修复规范](plans/2026-10-08-engineering-design-spec.md)，候选失败、冻结门槛、公开复验与限制见[验收报告](verification/2026-10-08-engineering-design.md)。

## 尚未验证的质量

人工 gold 仍是草稿；不能报告抽取 F1、SAME Precision、Recall@10 或路由准确率。超过 20,000 字符的文档仍会明确拒绝，完整语义分段和阶段缓存尚未实现。当前 190 篇输入的最大长度为 16,347 字符，但这不替代通用长文支持。
