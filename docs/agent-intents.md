“工程系统设计题，类似设计一个排行榜这种”按宽类别 SEARCH，排行榜是例子；“只要排行榜，其他系统不要”保持窄对象；“解释如何设计排行榜”进入 ANSWER。从 Agent 设计纠正为工程设计时清除模型推导的旧范围，保留用户明确指定的筛选。`coding_focus=ENGINEERING` 表示工程代码，不能当成系统设计类别硬筛；明确手写代码仍保留 ENGINEERING + CODE。

工程设计检索可使用 `preferred_question_type=SYSTEM_DESIGN` 软支路：不收窄完整资格范围，主支路保留其他类型候选，全部候选经任务类型、引文、对象和独立范围核验。当前来源上下文最多两次提问、每题 500 UTF-8 bytes，核验 hash 与 span；相邻题不能补成当前题缺少的设计任务。逐行结构异常排除并标记不完整，全批次候选身份和查询意图仍严格校验，必需核验失败不返回未验证列表。

“一共有多少条数据？”、“一共有多少道题？”和“这些有多少？”继承当前讨论范围。刚讨论 Redis 时统计 Redis；没有可恢复的讨论范围才统计全库。明确要求“全库 / 整个题库 / 所有分类”时清除隐含范围，当前显式 UI 筛选仍按契约生效，冲突时澄清。v11 曾把裸总量默认成全库，这条规则及其验收预期已更正。

“我说的是 Redis 的高频问题”只纠正或重申计数对象时，继续 COUNT；即使上一轮已经正确统计 Redis，也保留计数目标，直到用户明确提出列题、解释或其他新目标。模型结合 `conversation_focus` 和用户原话判断意图，宿主保存实际成功终结的目标、原句、筛选、排序、Top N、复习范围及 run ID。仅当前 focus 为 COUNT 时使用对应 `last_count` 连续计数；切到新列表后，数量追问采用新目标的范围。COUNT 和 ANSWER 保留原列表分页，NEXT 由独立 `list_goal` 恢复列表目标。

`page_size=20` 是单页大小。未明确要求 N 道时使用 `top_n=null`，列表可以继续翻页；旧模型自行填写的 Top20 也不能成为用户范围。COUNT 应用当前用户的复习状态筛选，未记录状态按 UNSEEN 处理。明确前 N 题中的计数使用 LIST 的 `pagination.result_total`，不能拿完整分类总量替代。

ANSWER 是受宿主校验的终结工具，生成文字不会成为新的题库记录。引用最多 10 道当前页题目，宿主重新读取来源并验证筛选范围。题库主要存题干与真实提问记录，技术解答属于模型生成的参考知识，界面会注明依据。没有本轮题库证据时，不能把回答标成来自题库。

对话保存结构化 `conversation_focus`、上一回答和独立计数回执；当前目标不随最近两条消息窗口淘汰。旧会话由 ContextCompiler 从可归属的上一回执、计划和计数范围兼容投影；旧 ANSWER 缺少范围依据时，不把旧分页筛选当作回答主题。模型上下文最多 24 KB；可选文字摘要会按预算压缩，题目 ID、筛选条件和数量事实保留，签名分页游标只由宿主使用。Pi 使用相同的有界证据，规划调用配置为 4、工具调用上限为 8；既有请求总模型调用上限为 6、截止为 180 秒，保留取消、幂等和复习写入授权检查。

单一大类的分布支持 `topic_level=L2`，例如把 Redis 分成性能、持久化等小类。请求 token 预算默认 96,000，规划输出上限为 4,096 tokens；规划调用配置为 4，与包含 embedding、重排和范围复核的请求总调用上限分别约束。
