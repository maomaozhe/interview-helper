# 面经项目评测系统搭建规范

日期：2026-10-05。本文定义可执行的评测基础设施、标注流程和验收条件。交付目标是能采集真实预测、复核依据、重算分数、比较版本并定位失败。框架验收与正式业务质量验收分别报告；人工测试金标尚未完成时，业务质量保持未验证。

## 1 参考与项目范围

参考美团技术团队的 [Agent评测漫谈](https://tech.meituan.com/2026/08/07/Agent-Evaluation.html)：同时检查结果与过程；将评判拆成可核验的小项；保留未知及人工裁决；从核心场景和好坏案例建立回归闭环。这些原则用于本项目的实现，文章里的业务成绩和阈值不作为本项目证据。

沿用 [V1 第13节](../implementation-spec-v1.md#13-评测设计与发布门槛) 的质量门槛，并补充独立任务分类、完整 SQL 集合和多轮 QueryAgent。实现位于 `eval/`；`evals/query-routing/` 的旧 Laya 探针保留为历史开发证据。

本阶段交付六类评分、分模块数据校验、真实采集适配器、快照约束、标注工作包、报告和版本比较。开放性语义判断由人工复核；LLM 可提供候选但不能自行确认 human_verified。首期不引入自动 LLM 裁判或训练平台。

## 2 数据与执行模式

数据集目录包含 `manifest.json` 和各任务 JSONL。兼容旧 manifest 内嵌数组。任务为 `extraction`、`task_labels`、`dedup`、`retrieval`、`routing`、`sql`。每条样本包含唯一 `id`、`split`、`group_id`、`tags`、`human_verified`；人工确认另需 reviewer、reviewed_at 和 guide_version。

三种用途严格区分：

- `dev`：允许 draft 与机器草稿，可运行及报告，门槛状态为 NOT_ELIGIBLE；数据缺少预期标签时仅采集预测。
- `test`：必须 frozen、人工确认、达到最低规模、满足快照与结构校验，才允许报告正式门槛。
- `fixture`：合成输入只验证框架，报告标明 SYNTHETIC，不计业务质量。

最低独立 test 规模为 extraction 30篇真实正例、dedup 150对、retrieval 50条正查询、routing 50个独立场景。教程等负文档和无答案查询另计。新增模块首版正式评测最低规模设为 task_labels 200条、sql 20个场景；可通过后续规范版本调整。分类及任务成功率阈值暂不预设，必须报告并在真实 dev 实验后另行版本化；所有正式模块失败数和未知判断均需展示。

样本按来源/转载组、问题对及反向形式、查询模板组和完整对话划分。已用于调参的案例进入 dev/regression。同 ID、重复文档、反向重复题对、跨划分 group 均拒绝。选择一个模块时只检查该模块最低规模，不因其他金标空缺而阻断开发。

## 3 快照与预测契约

实验快照绑定 corpus_revision、indexed_revision、task_annotation_revision、as_of、分类策略及测试用户。记录 Git commit、源码/配置/提示词 hash、模型标识及可获得的实际版本。凭据、带密码的数据库 URL、Authorization 不写入产物。

数据库导出使用同一只读事务；检索绑定 Elasticsearch 物理索引。采集前后核验版本，变化则实验 INVALID，不能混合计分。快照元信息和数据文件单独保存，原文按字节 SHA-256保存，字符跨度针对统一解码文本。

每条预测保存 id、failed、error_code、elapsed_ms、result、tool_trace、timings、usage。所有失败都保留一行；禁止只输出成功样本。模型调用串行复用已有 Linux 共享锁，显式限制调用数及 token；未知 usage 以保守预算占用处理，不记零成本。

预测采集与评分分开：采集不读取预期标签来生成结果；评分只比较已存结果与标签。离线重放可重算已有原始预测，不需要重复付费调用。运行目录使用唯一标识，禁止覆盖已有结果。

## 4 各模块评分

### 4.1 抽取

Gold 保存文档类型、正负样本类别、场次 metadata、原子问题、原文 spans、主题、类型与追问。问题使用独立 gold ID；预测使用独立 prediction ID。

评分必须从一对一 alignment 重算 TP/FP/FN，不接受预测自报计数。alignment 单独保存，绑定预测内容 hash、reviewer 和裁决时间。引用、场次、拆分或合并争议需人工裁决。缺少确认对齐时正例评测阻断，不能显示高分。失败或错误排除产生 gold 全量 FN；负文档另报排除正确性。

报告 micro P/R/F1、文档 macro、主题/类型准确率、公司/轮次等字段准确率、缺失字段幻觉数、引用有效率及追问 P/R。分母为零时 null；存在 FP/FN而无TP时 F1=0。原门槛为 P≥0.92、R≥0.88、F1≥0.90、公司≥0.95、轮次≥0.90、L1≥0.90、L2≥0.85；幻觉和无效引用为0。

### 4.2 任务分类与去重

任务分类分别报告 response_form、coding_focus 的准确率、Macro F1、混淆矩阵及联合完全正确率。预测 UNKNOWN 是弃权；gold UNKNOWN 单独统计。必须同时报已覆盖比例和已覆盖项准确率，不能通过大量弃权获得虚高整体成绩。

去重报告三分类 Macro F1、混淆矩阵、SAME P/R/F1与失败数；若提供候选集合，额外报告候选 Recall@10及包含候选漏召的端到端 SAME Recall。SAME P≥0.95、R≥0.85。embedding threshold 的对照预测可导入评分，阈值只在 dev 选择；未运行的消融明确列为 NOT_RUN。

### 4.3 检索

人工 relevance 为0/1/2。Gold语义ID通过单独人工核验的 canonical mapping 对应某一 corpus；不同等价组不能映射到同一 canonical，错误映射阻断实验。四路联合候选池用于标注，并记录池外补查与未标注结果数。

BM25、Dense、Hybrid、Hybrid+Rerank共用索引、过滤、查询向量和最终Top50。Rerank直接使用本次Hybrid同一候选列表，不能重新召回。报告 Recall@5/10、MRR@50、nDCG@10、P@10、无答案正确空结果率、失败数、分阶段延迟及usage。

重复结果视为无效预测，该查询记失败和零分；无答案查询执行失败不算正确空结果。失败/降级不能冒充指定管线的结果。Recall分母保留所有相关题；宽范围查询额外报告可达到的Recall上界。默认Recall@10≥0.85的门槛沿用原规范，但广泛列举任务交给SQL，不能删减相关题以达到该门槛。

### 4.4 SQL 与 QueryAgent

SQL样本用独立人工集合/独立SQL导出期望ID、顺序、次数、总数和分页；禁止调用同一待测函数产生期望值。直接结构化请求模型调用数必须为0。统计口径须对照gold分类和归并质量，不能仅证明系统内部一致。

Routing样本允许单轮或turns数组。每轮保存必要工具、禁止工具、允许替代工具计划、必要顺序、预期QuerySpec字段及终态断言。断言只支持受控路径和比较操作，不执行表达式或代码。允许比预期更多的非禁止工具，但计入效率；多轮场景必须所有轮次通过才算场景成功。

结果、过程、效率和写入约束分别记录可判定的PASS/FAIL/UNKNOWN及证据。缺失路径为UNKNOWN，正式任务成功不能将UNKNOWN当通过。Task Success由实际结果断言计算，不相信预测自报task_success。Tool Selection≥0.90；参数字段准确率、整计划准确率和任务成功率必须报告。越权写入为0。

必须覆盖工程代码/算法/SQL区分、Top N前后复习筛选、全范围与当前页、同一次occurrence约束、多轮继承/新话题重置、翻页后指代、分组排名、来源、幂等与写入范围。真实写评测只在隔离的eval用户API中执行，采集业务事件及状态。只读影子运行禁止写工具。

## 5 产物与反馈闭环

每次run输出manifest、config、原始predictions、per_sample.jsonl/csv、metrics、gates、bad_cases、summary.html/md；检索额外输出ablation.csv/md。逐样本记录失败阶段、断言、预期、实际和可回看轨迹。静态HTML支持按任务/状态筛选和展开案例，不引入外部服务。

门槛状态为 PASSED、BELOW_GATE、INVALID、NOT_ELIGIBLE 或 NOT_RUN。框架fixture成功不能显示业务发布通过。比较工具仅比较相同数据hash、快照和split，列出指标变化、新增失败、恢复及未覆盖项。小样本展示分母；不将开发性能当生产容量。

反馈导入工具从本地反馈生成去重的dev候选，保留来源与查询上下文，human_verified=false；不自动并入test。标注包提供原文、预测分离文件、空标签、对齐候选与review模板。人工修改生产分类与独立金标划分是两个步骤。

## 6 实施和验收顺序

1. 修正评分边界，强化分模块校验；边界回归先复现再通过。
2. 完成规则断言、alignment、六类评分与报告；缺失证据不通过。
3. 建立只读快照/生产结果导出、真实provider抽取/去重和固定候选检索采集；加入总预算和失败行。
4. 建立隔离评测API、SQL/多轮HTTP采集、标注包及反馈导入；默认不写真实用户状态。
5. 在合成fixture跑完整报告，在真实开发快照跑不调用模型的SQL采集，验证版本和零调用；模型评测在相应标注和预算准备后执行。
6. 加入离线CI命令和使用文档；记录当前人工gold未完成、消融/混合负载未运行等状态。

框架验收须覆盖重复ID/泄漏、重复ranking、失败负例、零F1、捏造TP、过期alignment、错误参数、禁止工具、缺失断言、多轮失败、过期快照、降级、预算、报告比较及路径边界。正式业务发布另需完成30/150/50/50金标、分类核验、真实消融和混合负载；这些数据准备不由代码或自动标签代替。
