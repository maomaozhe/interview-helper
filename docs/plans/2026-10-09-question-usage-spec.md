# 题目召回状态与复习覆盖 Spec

日期：2026-10-09。目标：让用户看到题库哪些题长期没有进入候选、哪些被筛掉或未返回、哪些返回过却尚未复习，并能从清单直接复习或记录问题。

## 口径

- `candidate_count`：成功完成的检索请求中，该标准题进入最终候选池的次数。BM25/DENSE 记录前 100 个候选；HYBRID 记录融合池（最多 50），不是全库相似度遍历次数。
- `accepted_count`：通过相关性核验的次数；包括分页截断的合格题，原始混合/关键词检索不冒充核验。
- `returned_count`：SEARCH 返回该题的次数。表示服务返回，不声称用户实际阅读。
- `listed_count`：SQL 题库浏览返回的次数，与检索召回分开。
- `review_count/status/last_reviewed_at`：使用既有、按账号隔离的复习状态；检索不会自动标记已复习。
- 每次完成的 query run / 直接 API 调用按题最多计一次；同 run 多工具取并集。receipt 重放、恢复重试不重复计数，重新检索的新 run 计新一次。失败、取消、未完成的 run 不计。部分核验保留候选观测，只对有效合格题计核验/返回。
- 使用期与面经日期分别命名。使用状态只统计 `usage_purpose=practice`；评测可显式指定 `evaluation`，保存但不纳入个人覆盖数据。
- 主题、公司等筛选决定当前展示的有效题目集合；次数来自这些题在当前账号、统计期内的全部使用记录，不限于同一查询筛选。复习状态采用全部历史记录，不受使用统计期截断。

## 持久化与版本

PostgreSQL 新增统计起点、完成请求、请求-标准题事件三张表。用唯一请求键与事务保证幂等，SQL 聚合生成计数，避免逐题查询和读改写丢计数。每次请求保留语料、索引/向量版本和候选观测完整性。向量、索引及 corpus/review revision 不因使用计数改变。

统计从迁移/建库启用时开始，旧日志不自动灌入：历史含大量评测且不同版本候选信息不完整。页面明确起点，零计数仅表示所选统计期内未观察到。缺少候选审计的兼容检索器记录“候选观测不完整”，不会把仅返回的 Top K 当成完整候选池。现有一次 REDIRECT 的标准题计数归到当前目标，并按 run 去重。

## API 与交互

- `GET /api/questions/usage`：复用主题、公司、轮次等事实筛选，支持使用期、未入候选、未返回、返回未复习、到期复习、按低召回/高召回/提问频次/最久未复习排序及分页。汇总以当前有效题库为分母，返回覆盖题数、运行观测完整性和统计起点。
- 题目详情显示个人累计候选/核验/返回/浏览/复习次数与最近时间。
- API 支持请求体/查询参数 `usage_purpose` 或请求头 `X-Usage-Purpose: evaluation`；显式值冲突返回错误。GET 模型中的默认值不视为用户显式指定。用途在幂等回执创建前确定，默认练习请求保持旧摘要兼容。
- 侧栏新增“使用与复习”页，提供范围筛选、统计卡片、排查解释、直接详情/复习、问题记录。浏览这个清单本身不增加召回次数，避免诊断时把零计数消掉。
- 默认空题库延后到首次打开时加载；历史回执只恢复展示。问题记录绑定当前题和范围，没有原查询时不显示重检按钮。
- 打开统计页时不在后台加载题库；首次切换到题库时才加载并计入浏览。GET 多值筛选使用重复参数，空列表不发送，避免未选择复习状态时触发校验错误。
- 清单为人工排查入口；不以零召回自动重嵌入、删题、调权，也不宣称本功能提升检索准确率。后续可在累积足够主题查询后加入索引完整性探测、冷门题主动复习、带留出集的改进建议。

## 验收

检索/SQL 浏览分别计数；候选但拒绝、合格但截断、异常候选、原始检索与缺审计正确区分；重放幂等、新 run 增量、多工具并集；失败/取消不计；评测排除、账号隔离、活跃语料范围和使用期筛选；复习/合并与稳定分页；迁移可在 PostgreSQL 与 SQLite 执行且保留旧行。以无模型测试与实际 BM25/SQL 使用闭环验收，并记录原始结果。浏览器验证统计、零召回筛选、详情、复习入口和窄屏。
