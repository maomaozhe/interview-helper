# 问答澄清与实时交互

## 现场证据

用户截图里的“系统设计题”“有哪些方向？”只有问句，没有选项。只读核对原会话 `20130cf6-36a2-4991-9974-998ddac20e10`：两轮 PG 回执均包含四个 `facts.meta.clarification.options`，当前前端重开历史可显示。截图与旧前端一致，但不能仅凭截图认定具体缓存原因。当前 `sendChat` 未传入阶段回调；SSE 虽记录阶段，用户仍只看到固定 loading；模型通常流式生成工具参数，因此普通 content delta 不会展示澄清问题。

## 本轮行为

1. 澄清用明确的选项卡，点击直接继续当前会话，同时支持自由输入。显示层兼容回执 meta 与 planning.spec 两种来源，不把选项仅藏在诊断 JSON。历史选项仍绑定原 run/version；已结束的澄清不可误提交到新主题。
2. 收到请求后立即反馈；从真实事件显示理解问题、筛选范围、向量检索、召回、相关性核验、整理结果，附实际已等待秒数。只有执行过的阶段出现在过程里，不造百分比。
3. 澄清问句随真实工具参数增量展示；局部 JSON、模型内部推理不展示。临时问句不可选择，成功提交回执后才启用选项。题目在核验完成后展示，不为动画延迟结果或伪造逐字输出。
4. 事件连接断开时，从最后事件序号恢复同一 run 的进度；不另开模型请求。重播去重，失败/取消/超时收口，已完成内容不被临时文本覆盖。
5. 停止操作放到输入框旁。用户主动向上阅读时不抢滚动。移动端选项和进度不横向溢出，减少动态效果设置生效。
6. HTML/资源版本可检查，服务更新后提示刷新；保留历史与会话。静态资源重新验证，避免沿用无版本旧资源。

## 验收

- 节点测试覆盖澄清兼容读取、过期按钮约束、事件顺序/去重、断线恢复同一 run、终态清理。
- Python 测试覆盖部分 JSON 字符串/转义安全，真实阶段转发、澄清不检索、流式事件以及代理路径资源版本。
- 浏览器用真实模型完成“系统设计题 → 点击方向”与执行过程观察，验证停止、刷新后历史恢复；保存截图和回执。沿用 Linux Docker 共享模型串行 gate，不从 Windows 直连模型。
- 本轮不改检索判分、候选排序、记忆启用策略或既有质量门禁；交互改善不代表召回质量已解决。

## 题库入口补齐

用户继续反馈 `/#library` 仍是旧交互。现场确认页面资源已是新版 `791537d24add`，但此前的实时呈现主要用于 `/#chat`。题库入口也应复用真实阶段和澄清问句增量，提供等待秒数、可折叠执行过程、靠近查询输入的停止按钮；完成后展示正式澄清选项。查询切换和停止必须清理旧进度，过期事件不能覆盖新的查询。题库顶部保留结构化检索和统计，增加明确的对话检索入口；查询进行中不触发界面更新刷新。部署后直接在 `/#library` 验收，保存页面版本、镜像、源码 hash 及浏览器证据。
