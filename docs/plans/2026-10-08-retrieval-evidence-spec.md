# 检索证据与历史重检补充 Spec

继续上一轮的局部改进，保留原始失败、已有反馈和发布门禁。

## 本轮目标

1. 每个通过语义筛选的候选给出两段来自候选自身的原文：对象证据和具体任务/现象证据。模型先固定查询对象及重点，再评分；宽泛领域、可能答案组件、未写出的故障不能补齐证据。host 校验引用确实来自本次提供的题干，两项证据缺失或虚构时不展示。引用校验只保证可核对，不等于语义正确，仍须真实对照测评。
2. 历史回答的重新检索携带来源 run。服务端校验用户及已完成状态，以原回执恢复查询目标、短答前上下文和筛选；当前显式筛选优先。生成新请求及新结果，保留原始用户措辞用于反馈记忆匹配。不得回放旧结果、恢复旧写授权或继续过期游标。
   LIST/STATS 将当轮明确 UI 筛选保存为列表范围来源快照；NEXT 沿用该快照。重检 NEXT 的原公司等筛选由宿主保持，当前显式值或 null 可覆盖；模型推断的标签仍作为上下文。新列表替换快照，SEARCH 清理。旧回执缺快照时继续兼容，不伪造其来源。
3. 澄清选项和“下一页”只属于当前会话最新可继续的回答；已完成的历史选项应禁用，点击处理同样核对绑定。反馈、详情与重新检索仍可使用原回答。
4. 完整旧候选池确认 Harness 记忆题未进入 Top50。新增可选、最多三条的模型规划词法分支，只用于同一对象的并列子任务。主 RRF 前20保留，分支按轮转各补最多10个新候选，再补足到50；共用 SQL eligibility 和 ES PIT，只增加 BM25 请求，不增加 embedding/模型调用。所有候选仍由同一原始意图核验。分支失败明确返回可重试错误，不冒充部分成功。
   最终展示保留重排前5；只为尚未覆盖的分支各补至多一条已通过的候选，其余恢复 grade/model 排序。分支不得主导整页或引回被拒绝的候选。保留首次轮转策略挤掉已接受第13名的失败，再对同一已接受池重放及真实 Harness 子集测评；子集不冒充完整十轮重跑。
5. 搜索工具使用专属计数合同：`top_n=null`，`page_size` 为 1–50。模型应第一次输出合法参数，不把 SQL 的全局 Top N 迁移到语义搜索。验收记录首次 503 及重复规划原因，修复后另留回执与实际规划次数。
6. 扩展召回与相关性目标分离。`relevance_query` 保留用户明确对象及任务，消歧短答可以恢复上下文，不得增加用户未请求的子模块条件。普通 Agent 应用设计不自动收窄成 Harness 运行框架；词法分支扩召回不改变判断目标。保留原始用户措辞与上下文来源，测试不能仅检查 prompt 文字。
7. 真实测量发现单次合法规划与证据重排已耗尽 60 秒。整轮默认预算适配为 90 秒，规划/工具/模型门次数和 token 上限保持，用户仍可取消；不得将增加预算称作降低延迟或解决 Provider 的畸形参数。以新完整回执验证，保留原 60 秒失败。

## 检索测评

- 在修改部署前保存 v6 的完整 Top50 候选池、全量已接受候选、截断后的返回、原查询计划与耗时；候选部署使用完全相同的池与相关性意图重排，隔离召回变化和规划随机性。
- 四项真实查询为 Agent 设计、Harness、秒杀、线上内存增长。逐条核对上一轮两个弱相关结果及已知 Harness 正例在哪层退出，不能以硬编码 ID 调整排名。
- 若正例在 Top50 之外，单独记录召回瓶颈；若在已接受池但 Top15 之外，记录截断与排序，不把它称作全库漏召回。没有完整独立人工判断，不报告全库 Recall。
- 留证输出 token、耗时、证据校验、工程回归与真实页面操作。保留 v6 和候选原始回执；本轮是开发回归，不是未见集或独立人工 Gold。
- 真实多轮另验：已切换话题后重检原短答，仍恢复原目标；Redis 列表→下一页→绑定第二轮重新检索，应回原范围第一页且原 UI 公司筛选继续约束宿主。字段省略与显式默认值对重检含义不同，幂等摘要须区分。
- Redis 分页前置条件必须是无全局 Top N 的 LIST、有下一页且 NEXT 返回非空、不重复的题目。仅改变页大小；“返回两道”表示总量时不能当作真实分页通过。首轮无效验收保留，修正后使用新文件。

## 完成条件

有可核对的代码与 Spec、来源绑定和隔离测试、真实同池 before/after 以及本机 UI 验收。对未解决残差和延迟成本明确报告；原 V1 阻断不放宽。
