# 访问管理与运行看板 Spec

状态：已实现、测试、验收并正式上线。日期：2026-10-09。适用项目：面经研习现有 FastAPI / PostgreSQL / SSH 正式服务。验收结果见 [验收报告](../verification/2026-10-09-access-panel.md)。

## 1. 目标与交付

管理员在 `/admin` 查看真实访客、设备对应的公网出口 IP、请求量、对话用量、QPS、错误率与延迟，点击封禁或解除封禁，并通过 Web 开关配置对话配额和请求限流。交付包括本规范、实现、自动化测试、真实浏览器验收、正式部署回执和回退方案。

用户已明确要求测试、验收、上线，并补充「可以做一个开关，web点击配置」。配额与限流都在 Web 表单保存后生效；初次上线两个开关默认关闭，预置配额为每天 10 次。修改立即影响新请求，已有请求允许完成。封禁设备与封禁 IP 是分别可操作的功能。

## 2. 身份与统计口径

| 名称 | 定义 |
| --- | --- |
| 访客 / UV | 选定窗口内有业务访问的匿名设备 Cookie 去重数。Cookie 是服务端签名随机 ID，不使用浏览器指纹。 |
| 设备 | 浏览器中的签名 Cookie 身份，展示 User-Agent 推导的设备和浏览器。换浏览器、清 Cookie 可能成为新设备，不等于自然人。 |
| IP | 服务端取得的公网出口地址。同一 NAT / 公司 / 学校可能共享 IP；不能取得客户端局域网 IP。 |
| PV | 工作台首页导航请求次数；静态资源、管理页、健康探针、内部 Agent 调用不计 PV。 |
| 业务请求数 | 业务 API 和首页请求，包含失败、封禁及限流响应；管理接口、静态文件、健康探针、内部调用不计。 |
| 对话 / 配额用量 | 通过校验后准入的一次新查询轮次。新建空会话、读历史、SSE 重连、轮询、重复提交同一 request_id 不加次数。准入后模型失败也计次，避免通过失败无限消耗资源。 |
| 当前 QPS | 最近完整口径 60 秒内业务请求数 / 60，单位请求/秒。 |
| 峰值 QPS | 所选窗口内最高单秒业务请求数，单位请求/秒。 |
| 趋势 QPS | 每个时间桶请求数 / 桶秒数。无请求的时间桶补零，避免将一分钟请求量标成 QPS。 |
| 错误率 | 业务请求的 HTTP 5xx 数 / 业务请求总数；403/429 单列拒绝请求，不算服务端错误。 |
| P95 | 所选窗口业务 HTTP 响应延迟第 95 百分位。异步对话提交耗时不代表模型完整生成耗时，SSE 以响应建立为界；页面注明口径。 |

看板支持最近 1 小时、24 小时、7 天，默认 24 小时；每 10 秒刷新，后台标签页暂停刷新。时间显示使用 Asia/Shanghai。采集从部署时开始，历史空白不能用随机数据补齐。配额关闭时仍记录准入用量。

现有项目仍是共享个人工作区。本次增加访问管理与成本控制，不把匿名 Cookie 当成登录系统，也不宣称提供多租户会话隔离。未来可增加真实账号并将主体切换为账号 ID。

## 3. 管理员入口

- 现有工作台提供「访问管理」入口，独立 `/admin` 页面，手机和桌面均可使用。
- 独立 `ADMIN_ACCESS_TOKEN` 通过部署环境配置，不复用模型密钥或内部 Agent 密钥；不配置时管理接口不可用。
- 登录成功签发短时 HttpOnly / SameSite=Strict 会话 Cookie；HTTPS 使用 Secure。页面不把管理密钥写入 localStorage 或 sessionStorage，登录成功清空输入。
- 管理 API 全部鉴权，未登录不能读取 IP、访问数据、策略或审计。支持 Bearer 密钥用于部署验收，不在页面或日志回显。
- 写操作必须带专用请求头并进行同源检查，策略修改使用版本比较，冲突返回 409 并重新加载，不覆盖其他管理员更新。
- 登录失败有独立频率保护，不受业务开关影响；管理页不受业务封禁约束，以便解除误封。退出撤销当前浏览器登录。

## 4. 访客列表与封禁

分页展示设备 ID、设备类型、浏览器、最新 IP、首次 / 最近访问、累计 PV、业务请求与对话准入次数、当前配额用量、设备与 IP 封禁状态。支持按 ID / IP / User-Agent 搜索，分页每页 20 条。

设备封禁和 IP 封禁分别保存。设备换 IP 后设备封禁继续生效；IP 封禁覆盖该出口的新访问设备。解除设备封禁不会解除对应 IP 封禁，反之亦然。页面操作前明确目标，IP 封禁提示共享出口可能影响其他设备，可填写原因。封禁返回 403 和稳定错误码，所有业务入口统一检查，包括直接 API、历史与 SSE 新连接；健康、静态资源、管理员恢复与经独立鉴权的内部 Agent 通道保留。

不根据客户端随意提供的 `X-Forwarded-For` 封禁他人。关闭 Uvicorn 自动代理头解析，仅信任部署明确指定的代理 CIDR；从真实 socket peer 开始由右向左剥离可信代理链，拒绝不可信来源的转发头。正式两级 Caddy 必须保持真实来源链，并验证伪造转发头不能改变识别结果。

## 5. Web 策略配置

| 配置 | 默认 | 约束与行为 |
| --- | --- | --- |
| 对话配额开关 | 关闭 | 保存后对新查询生效；关闭时继续记录用量。 |
| 最大轮次 | 10 | 正整数，服务端校验上限。 |
| 配额周期 | DAY | DAY 在北京时间每日 00:00 重置；LIFETIME 累计到管理员重置。 |
| 配额主体 | DEVICE | 可选 DEVICE / IP。DEVICE 精确到匿名浏览器；IP 可防清 Cookie 绕过，但共享出口共用额度。 |
| 查询限流开关 | 关闭 | 约束同 IP 的新查询准入，避免 SSE / 轮询被限流。 |
| 每分钟准入上限 | 60 | 正整数，所有昂贵查询入口共用。 |

第 N+1 个新请求在调用模型前拒绝，返回 429、稳定错误码和可理解的消息。每日配额与分钟限流返回 `Retry-After`；累计配额明确要求管理员重置。具备结果重放能力的 Query / 连续对话接口，相同 ID 和相同内容重放不重复计次；相同 ID 不同内容返回冲突。直接 GET 检索与未启用 Query Router 的旧 Chat 没有结果重放能力，每次实际调用都计次，即使传入相同请求 ID。多个并发请求、多个应用实例和重启均不能超额：使用数据库唯一约束与行锁 / 原子更新，不能依赖单进程内存计数。

覆盖连续对话发送、同步 Query、题库自然语言查询、旧 Chat 与直接模型检索入口。纯 SQL 浏览不消耗对话配额或查询限流次数，包括工作台初始化自动调用的结构化 `/api/questions/list` POST；该入口使用严格结构化 schema，只执行 SQL，不调用模型，因此不能借此绕过模型查询限制。管理员可重置选定主体配额，重置有审计；变更周期 / 主体不会凭空清空对应已计用量。

## 6. API 与持久化

管理响应采用 `{data: ...}`。主要接口如下：

| 接口 | 用途 |
| --- | --- |
| POST / DELETE / GET `/api/admin/session` | 登录、退出、登录状态。 |
| GET `/api/admin/overview?window=24h` | 概览与时间桶趋势。 |
| GET `/api/admin/visitors?q=&page=1&page_size=20` | 搜索与分页访客。 |
| GET / PATCH `/api/admin/policy` | 读取和保存带版本的限额策略。 |
| PATCH `/api/admin/visitors/{id}` | 设备封禁 / 解除。 |
| PATCH `/api/admin/ips` | 精确 IP 封禁 / 解除。 |
| POST `/api/admin/visitors/{id}/reset-quota` | 按当前配置主体重置配额。 |
| GET `/api/admin/audit` | 最近管理操作记录。 |

新增表仅保存访问身份、策略、配额准入、请求指标与管理审计，不保存对话正文、模型凭据或管理员密钥。设备 IP 与 UA 是受管理鉴权保护的运行数据，UA 长度有界；路径归一化避免记录带 ID 的任意路径和查询内容。业务请求指标保留 7 天、审计保留 30 天，清理工作有界。设备与策略长期保存，累计配额不能因指标清理而归零。

新增 Alembic 迁移采用增量建表，保留现有语料、索引、会话、模型版本和个人复习数据。健康探针不依赖管理登录。

## 7. 验收清单

1. 未鉴权访问管理数据被拒绝，未配置密钥明确失败；伪造 / 篡改会话无效，跨站写操作被拒绝。
2. 真实浏览器首次访问计一个设备，刷新增加 PV 而不增加设备数；不同 Cookie 为不同设备，IP 可共享。
3. 转发头信任测试覆盖直连伪造、可信单级 / 多级代理、IPv4 / IPv6；正式真实公网请求能取得实际出口 IP。
4. Web 点击封禁使同设备业务请求 403，解除恢复；IP 封禁覆盖新设备；管理页仍可恢复操作。
5. Web 开启配额并设置小额上限，N 次准入、第 N+1 次 429；重复 ID 不加计，非法内容不加计；并发请求准确限制；关闭开关恢复准入。
6. DAY 北京零点、LIFETIME、DEVICE / IP 主体、手动重置和服务重启均符合口径；所有昂贵查询入口不能绕过。
7. 独立开启 IP 每分钟限流能返回 429，关闭恢复；轮询与 SSE 重连不消耗查询次数。
8. 指标按真实请求复算，QPS 桶分母正确，静态 / 管理 / 健康不会污染；403/429 与5xx区别明确；无数据时展示真实空状态。
9. 策略修改、封禁、解封、重置与失败登录有审计，不泄露 token；恶意 UA 不执行脚本。
10. 桌面与390像素页面可浏览、搜索、分页、配置和操作；登录、加载、错误、空状态明确。
11. 相关自动化、完整 Python 与现有 Node 回归通过；如有失败保留首次记录并修复后重跑。
12. 上线前冻结文件清单及 SHA、备份受影响文件和代理 / systemd 配置、等待在途查询完成。上线后核正式迁移、资源 SHA、鉴权、真实访客、可逆测试主体封禁 / 限额和健康；还原验收策略。回退保留新增运行数据，不降级或删除已有语料。
