# 对话检索、澄清与反馈记忆 Spec

日期：2026-10-08。基于现有 Pi QueryAgent、PG QueryState、SQL 列表和真实反馈继续实现；保留工作区已有质量实验及原发布门禁。

## 问题与证据

1. `agent场景设计题` 的反馈请求 `ffafde8a-f40e-46cc-bb17-78ba2716379b` 执行 HYBRID / NOT_REQUESTED。20 条中出现令牌桶、分布式 ID、普通缓存等不含 Agent 任务的问题。RRF 排名不是相关性判定，按页大小截断会填入弱相关候选。
2. harness 反馈的两次历史请求只检索 `harness`，未表达上下文、记忆、工具编排、执行恢复的意图，同时混入哈希表等题。只做严格词匹配会漏召回；只做领域扩展会引入噪声。
3. CLARIFY 已有工具动作，但没有保存待澄清目标和选项；历史 API 只给最近十轮且没有会话列表；恢复的回答与新回答使用不同渲染逻辑，反馈缺原回答、run 和完整结果。

## 目标与交互

- 首页以对话为主要入口，灰白工作台、会话侧栏、居中消息、底部输入框；题库、分类核验、导入和反馈入口继续可达。
- 模型判断信息是否会改变候选集合。仅缺领域且存在明显多义时先 CLARIFY：例如没有上下文的“场景设计题”询问 Agent 应用、业务系统、线上排障或全部。不要求用户填写公司/年限等非必要字段。
- “Agent 场景设计”“秒杀系统设计”“线上内存上涨排查”已经明确，直接检索；明确“全部”可直接浏览完整 SQL 类别。上下文或明确保存的设计方向足够时不重复询问。
- 澄清响应只有问题和最多四个可点击答案，不发起 ES/embedding/rerank。保存原请求、待确认槽位及选项。下一轮短答与原目标共同规划；新话题和完成查询清除 pending。
- 每轮显示回答、真实题目、解释本次检索范围、相关性状态、来源、反馈和“重新检索”。恢复历史与新回答使用同一渲染和事件绑定。失败恢复复用 request_id；重新检索使用新 request_id。

## 检索契约

- 自然语言语义检索默认 HYBRID_RERANK；类别榜单、全局 Top N 和统计继续 SQL。BM25/DENSE/HYBRID 作为明确选择保留，标记为未经语义筛选。
- 规划输出具体意图：对象 + 任务 + 条件。harness 按 Agent 运行框架扩展到 context/memory/tool orchestration/recovery；保留原对象，避免只用泛词“设计”。不因为 Agent 查询强制单个 taxonomy 小类，避免漏掉跨分类真题。
- `search_query` 用于语义扩展和候选召回；`relevance_query` 恢复原始需求的对象、任务和约束，用于相关性核验。推测的答案术语不能扩大判定范围：秒杀召回可以加入 Redis/MQ，普通 Redis 或异步安全题不能因此被判为秒杀设计相关。省略回复需从待澄清目标或上一轮计划恢复意图。
- 重排按对象、任务和约束联合相关性评分；仅共享“场景/设计/系统”不足。明确 Agent 查询不能拿普通后端设计补数量；harness 的上下文/记忆设计可以相关，即便题干没有 harness 一词。
- grade >= 2 才呈现。相关不足如实返回少量或空集；重排失败/预算不足时呈现“相关性核验未完成”及空结果，不把未筛选候选当作已验证答案。显式原始检索可以查看候选。
- 保存真实 requested/executed pipeline、候选数、保留数、重排版本；查询版本与语料版本一起留证。

## 会话、记忆与改进

- PG 保存会话及轮次，新增可搜索、分页的会话列表与轮次分页；游标绑定用户。浏览历史不重新调用模型。
- 会话上下文：pending clarification、当前查询目标、当前页和临时筛选。长期偏好：增加设计方向，明确保存，可查看/删除，当前明确需求优先。
- 反馈必须带 run_id/request_id/conversation_id、原回答、完整结果、查询计划和版本。服务端从属于当前用户的 PG 回执补全权威证据；客户端上下文作为补充，不能伪造权威结果。
- 保存反馈后可立即携带 feedback_id 重新检索；模型读用户纠正，重排仍对真实题目核验。
- 自进化第一阶段实现用户范围的经验闭环：反馈自动成为可检查的改进样本；明确“记住纠正”后保存有版本的窄范围查询经验，仅相同查询触发，可停用/撤销。自动生成回归样本导出，原反馈和 before/after 回执保留。系统提示词、题库标签和全局模型不会由单次反馈直接改写。
- 经验是有来源的检索上下文，不能授权复习写入或覆盖明确筛选。相关经验最多三条、长度有界，Context Compiler 继续限制 24 KB。

## 实现范围

QuerySpec 新增澄清选项和独立相关性意图；QueryState 投影增加 pending。query_agent_v9 保留 v7 的字段清除、任务维度及 SQL 规则，优先判断已明确的对象；v8 首测的过度澄清与泛化结果另存，不覆盖失败。新增用户范围反馈经验服务和历史分页 API。复用 UserPreference 存储设计方向及经验，使用现有版本冲突检查，无新增事实表或标签迁移。前端统一渲染、会话浏览、反馈/重试/重新检索和记忆管理。

## 验收与测评

1. 先封存本轮场景协议，再采集旧部署和候选的真实 Pi/模型/ES 输出；记录版本、调用、耗时、完整题目和轨迹。已知反馈为回归，新增查询为开发挑战，不冒充独立人工 Gold。
2. 无上下文的模糊设计请求应 CLARIFY，ES 调用为 0；回答 Agent 后应 SEARCH，明确领域和已知 context 请求不应过度澄清；新话题不继承旧领域。
3. 已知 Agent 反馈中令牌桶、分布式 ID、普通缓存三个负例应退出结果；harness 结果按原题干逐条裁决，并检查 context/memory 正例召回。比较相关 Precision、返回量及已知正例命中，不用不完整候选池报告全库 Recall。
4. 覆盖 idempotency、取消/恢复、过期版本、用户隔离、历史分页、来源/反馈完整性、经验触发与撤销、上下文预算；Python/Pi/前端现有回归不得因本轮功能退化。
5. 在真实本机 8000 完成对话、澄清选项、历史恢复、反馈重检、记忆撤销与窄屏视觉检查。记录失败和边界，不降低旧质量门槛。
