# 工程系统设计题检索修复

状态：2026-10-09 已发布并通过公开原会话复验。问题与方案起于 2026-10-08；实际结果和已知限制见 [验收报告](../verification/2026-10-08-engineering-design.md)，版本和部署哈希见 [证据索引](../verification/2026-10-08-engineering-design.evidence.json)。

用户报告：线上会话从 Agent 设计纠正为“工程系统设计题，类似设计一个排行榜这种”，最终只返回一题。

## 已确认原因

线上 r293 / query_agent_v12 / rerank_v10 的实际回执将排行榜例子写入唯一 relevance focus，并沿用 SYSTEM_DESIGN + ENGINEERING + KNOWN 硬过滤。全库独立补查的 23 个主设计参考中，14 个已在该回执的 Top50，但被判 NEIGHBOR；4 个不满足错误硬筛；4 个未入池。不是语料只有一道工程设计题。

## 修改边界

- v13 规划区分“宽类别 + 例子”与“只要某业务对象”，前者按类别保留其他工程系统设计，后者维持窄范围。
- 工程系统/业务系统/架构设计使用语义 SEARCH，不能把 coding_focus 的工程编程含义当作系统设计领域；纠正隐式范围时清除旧分类与任务限制，继续遵守显式 UI 筛选。
- 技术解答仍使用 ANSWER；明确手写代码保留 ENGINEERING + CODE。
- 重排补充同一筛选范围内的原始问法和不可变来源语境。来源须验证 hash 和 span；附近内容仅帮助判断题型，支持对象/任务的引文仍限定当前题干，不能拿相邻题凑证据。最多两次提问、每题 500 UTF-8 bytes，控制模型预算。
- 重排 schema 显式区分独立设计、项目复述、代码、局部追问与知识解释。用户要独立设计时，宿主要求 DESIGN_TASK 及当前题干或已验证原问法的连续证据，再执行原有对象/焦点校验；邻近主设计不能证明当前局部题是主设计。其他任务保持其范围，模型故障不能退回未验证列表。
- 召回采用真实题干的通用问法“场景题/如何设计/一个系统”等，区分规划用的概念分类与搜索用的表达，不把参考题的业务名或 ID 填入查询。
- 增加独立范围复核，按当前题要求交付的设计单位判断完整工程机制与局部处理，复核不接收上游评分或结论。规划调用配置 4、既有请求总调用上限 6、截止 180 秒。
- SYSTEM_DESIGN 作为可选软候选支路，不改变完整 eligibility。已有 facets 时保留 broad10 + preferred30 + facets 剩余额度，无 facets 时 broad20 + preferred30，总池最多 50；所有结果都通过同一任务/对象/范围校验。软支路词法/语义 RRF 权重为 1:2，主支路仍等权，实际权重进入回执。
- SSH 发布在实际线上包上叠加版本声明、配置允许值、v13 prompt 和原文语境 callback，外加 query_service 的软 hint 转发及 partial 状态传递，共九个文件；基于线上 r10 的增量 r14，不夹带本地 r16/r19 其他实验。批次意图和完整唯一 ID 集合严格校验，每行独立校验结构，坏行排除并单列，不修补模型内容或放宽语义门禁。
- Pi 工具 schema 白名单须声明软 hint，增加精确线上 runtime 的一行补丁为第十文件，发布时同时备份/重启 Pi。以 Node 真实工具 schema/HTTP 测试及 Python internal-tool HTTP/SQL/回执测试覆盖整条字段传递链路。
