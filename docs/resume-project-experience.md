# 面经知识库：简历项目与面试说明

更新：2026-10-06。当前可以形成一份有实验依据的项目经历；完整 V1 质量验收仍被阻断。下面的数字是固定语料上的离线实验或回归结果，不能写成线上用户效果。最新分类挑战、查询首测及标注修订见 [本轮报告](verification/2026-10-06-quality-refinement.md)，判断池扩充见 [上轮报告](verification/2026-10-06-quality-optimization.md)，历史运行仍保留在 [初轮报告](verification/2026-10-06-resume-quality.md)。

## 可直接使用的项目描述

**面经知识库与查询 Agent｜Python / PostgreSQL / Elasticsearch / Pi Agent Loop**

面向面试复习，将 172 篇有效面经、2,771 次真实提问整理为 2,452 道可追溯标准题，支持完整范围统计、语义检索、连续筛选与复习状态管理。

- **分层评测与分类：** 构建覆盖抽取、任务分类、语义去重、检索、查询轨迹及 SQL 的版本化评测与发布阻断流程；冻结原文证据、预测和 Regression Diff。在同语料、来源不相交的 **200 条**首次分类测试上，区分机制说明与组件构造，将联合正确率从 **60.5% 提升至 96%**、工程类误报从 **74 条降至 3 条**；另增 **200 条工程挑战**检验误报与漏判，工程 Precision / Recall 未达标，候选版本保留阻断。
- **检索与统计：** 实现 Exact SQL 与 Semantic Retrieval 双执行路径，在同一 **55 查询**集上比较 BM25、Dense、RRF Hybrid 与 Rerank；新增 **828 条**相关性裁决，覆盖四路 Top 10，识别重排过滤造成的召回损失。**20 组**完整范围统计与全分页结果通过独立事实快照核对，SQL 路径无需模型调用。
- **Agent Harness：** 基于固定版本 Pi Loop 实现结构化 QueryState、24 KB 上下文编译、按状态裁剪工具、主机侧写权限校验及请求幂等；候选查询版本在 **50 场景已见回归**上从 **43/50 恢复到 50/50**，另 **50 个新组合、62 轮**原始首测通过 **46/50**；版本化记录参数参考错误、额外筛选和上下文清除失败，两组观察到越权写入均为 **0 次**。
- **去重候选性能：** 实现向量化精确检索与 HNSW 索引候选结合增量精确扫描、二次排序的候选策略；在 2,668 向量、60 次缓存探针中，相对全量精确 Top 10 的候选召回率 **100%**，候选计算 P95 从 Python 精确扫描的 **330 ms 降至 114 ms（65.4%）**；当前小规模语料默认使用向量化精确路径。

版面不足时保留前三条，把最后一条缩为检索条目的后半句。面向 RAG / Agent 工程岗位，先讲双执行路径和 Harness，再用评测解释取舍。

## Fast Decision 的可用措辞

可以作为面试中的实验取舍，暂不建议写成主成果：

> 实现类型化 System-One 决策接口、主机侧置信度校准与 Frontier Fallback，对私有部署的 Laya / Qwen 小模型开展业务评测；使用独立 60 条校准、50 条测试场景及版本绑定准入规则，识别高置信错误并拒绝启用未达标 Fast Path。

Qwen3-1.7B 当前完整类型化决策正确率为校准集 **18/60**、独立测试集 **10/50**。没有合格接管阈值，不能填写“大模型调用减少 xx%”“路由 P95 降低 xx%”或“保持 Task Success 的生产收益”。小模型置信度是生成 token 概率的汇总，不是业务正确概率。

完整链路另测 10 条已见场景：直接 Pi 与 Qwen 后回退都通过 9/10，Frontier 都调用 10 次；后者多出 10 次小模型调用，配对耗时中位数增加 3.59 秒。这个取舍已有实际调用证据；10 条顺序诊断不足以证明普遍性能，更不产生调用节省。

## 面试时必须说清的口径

| 追问 | 可以回答的事实 |
|---|---|
| 你有人工 Gold 吗？ | 主要由 Agent 按原文独立审核并封存，整行 `human_verified=false`；抽取/分类另有用户对 3 个歧义字段的明确裁决。属于参考金标，不称为大规模人工标注。 |
| 98% 和 100% 是什么成功率？ | 98% 是旧固定 50 场景上的已见回归；100% 是另一组 50 场景首测 43/50 后，候选 v7 修复重测的结果。新备用 50 场景原始首测为 46/50，不能用回归满分代替泛化。原有机器分类仍作为 SQL 范围基准。 |
| 为什么还有 96% 查询重评分？ | 备用参考集两处 round 写成了中文显示名，接口要求 FIRST/SECOND。按原始请求和固定事实另建修订版，同一预测重评分 48/50；原始 46/50 保留，不声称模型提升，全部 50 场景和两个真实失败保留。 |
| 是 Context Compiler 单独带来 14 个百分点吗？ | 不能作此归因。比较过程中还有 query prompt 与 required tool calling 协议迭代，属于整体查询路径回归改善；缺少 Compiler 独立消融。 |
| 测试集是否被用于修复？ | 原查询和去重案例已用于诊断与迭代，属于回归集。分类原 200 条来源留出如今也归为已见回归；另有 200 条预测前封存、题目不相交的工程挑战，但来源仍共享。查询继续封存未运行的 50 场景 / 95 轮。首次结果保留，Fast Decision 只在独立校准集选阈值。 |
| 为什么统计不用 RAG？ | Top K 检索不能证明完整范围的频次与排名。SQL 在同一 occurrence 上应用筛选并聚合，独立导出的原始事实用另一实现核对排序、计数与分页覆盖。 |
| Hybrid 或 Rerank 一定优于 Dense 吗？ | 不成立。扩充判断池后，Dense Recall@10 为 69.04%、NDCG@10 为 0.852；Hybrid + Rerank 为 60.29%、0.849。四路 Top 10 已全部裁决，深层排序和池外相关项仍不完整。 |
| 为什么删除原来的 18.9% 提升主张？ | 那是较小判断池下 Rerank 相对 Hybrid 的 NDCG 提升，原始报告继续保留。新增相关项改变了召回分母和排序评价，旧数字不能代表当前质量，更不能与新池直接比较为模型退化。 |
| 96% 或 98.5% 是否证明工程筛选可靠？ | 没有。原 200 条仅 3 条工程正例，v6/v7 工程 Precision 为 50% / 75%。新增挑战包含 15 条工程正例，v7 联合正确率 93.5%，但工程 Precision / Recall 只有 70.59% / 80%，低于 90% / 85% 门槛。整体正确率受 NONE 大类占比影响。 |
| 有延迟或调用数改善吗？ | ANN 候选阶段有实测提速。查询回归 P95 反而从约 13.0 秒升到 19.1 秒；Rerank 引入模型耗时。本批不宣称整链路降延迟、降模型调用。 |
| ANN 100% 说明什么？ | 60 条已缓存标准题向量的近邻结果与全量精确 Top 10 一致，不是语义 SAME 召回率，也不是新原文导入的端到端成功率。 |
| ANN 为何包含增量扫描？ | 发布索引中有 2,452 条向量，活动候选池另有 216 条；对未入索引、新增、变化或版本不一致项精确比较，再与 ANN 结果合并，避免只查已发布索引而漏候选。 |
| 动态工具是否足够防止写错？ | 工具暴露只是第一层；主机在每次调用时重算权限，要求当前明确写指令、当前展示题目范围、状态值、稳定 action ID 和幂等事务。模型不能通过参数给自己授权。 |
| 提前结束会丢结果吗？ | 完整事实由主机保存和返回，模型只接收有限预览；完整结果工具执行后终止不必要的生成，保留当前页全部 ID 和后续分页状态。 |
| Fast Path 为什么不开？ | 高置信度仍错：校准阈值 0.99 时接收 20 条，其中 12 条错误；更高阈值不能同时满足最少 20 条接收与零观察错误的准入规则。保留 Pi 作为正式路由。 |
| 整体是否上线验收通过？ | 本地功能栈已部署，完整质量门禁仍为 BLOCKED、有 6 项阻断；抽取元信息/小类、工程 Precision / Recall、去重精度、检索 Recall 和两组分类回归未达标。查询和 SQL 的模块通过不能抵消这些失败，候选 Prompt 仍未默认启用。 |

## 接下来最值得补的证据

1. 工程挑战已扩到 200 条、15 条明确正例，下一步修复构造/算法边界及代码形式漏判，并另冻结未见来源测试；现有 611 条已观察样本继续作为回归。
2. 抽取已恢复整篇的 19 题、排除两个汇编负例；最新 32 篇回归 F1 为 92.09%、大类 90.87%、小类 80.65%，51 个 FN 保留。继续修复轮次错位、空值误填和多问题合并；实验输出未发布到原题库。
3. 向四路 Top 10 之外补查相关项和 hard negatives；评估候选截断与重排过滤策略。去重完整链路只能说明所测阶段和指定题对，不能替代整体 SAME Precision。
4. 修复只清除单一岗位条件及口述/任务焦点独立性；下一轮 50 场景 / 95 轮仍未运行。补 Compiler / Tool Policy 独立消融后再决定是否能写 token / 成本下降；Fast Decision 继续关闭。

这些是后续计划，不能混进上面的已实现成绩。包装可以突出真实工程取舍和测量口径；没有实现或没有测到的收益保持为空。
